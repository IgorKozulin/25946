# Задача 6 — поиск строки с alarm

Это самостоятельная версия задачи 5 с таймером. На ввод каждого номера,
включая Enter, даётся 5 секунд. После таймаута программа печатает весь файл
и завершается успешно. После своевременного ввода выбранная строка выводится,
а следующий запрос получает новые 5 секунд. Номер 0 завершает работу сразу.

## Сборка и запуск

```sh
cd ~/25946/d.lukhanin1/Task_6
make
./line_lookup_alarm test.txt --table
```

Введите `2` и Enter раньше пяти секунд, затем `0` и Enter. Для проверки
таймаута запустите снова и ничего не вводите: через пять секунд появится весь
файл. Ввести цифру без Enter недостаточно.

```sh
printf '2\n0\n' | ./line_lookup_alarm test.txt
```

EOF означает окончание ввода и выход. Поэтому пустой закрытый канал не
проверяет таймаут: для таймаута источник ввода должен оставаться открытым.

## Что добавлено к задаче 5

Таблица строк и доступ к файлу через `open/read/lseek/close` сохранены.
`setup_timer` регистрирует `alarm_handler` через `sigaction`. Перед чтением
каждого номера `read_query` вызывает `alarm(5)`. По истечении времени ядро
посылает процессу `SIGALRM`. После завершения ввода `alarm(0)` отменяет таймер.

Обработчик только устанавливает `timed_out = 1`. Флаг имеет тип
`volatile sig_atomic_t`: он подходит для обмена простым состоянием между
обработчиком и основным кодом. `volatile` требует обращаться к актуальному
значению; `sig_atomic_t` допускает такое присваивание в обработчике.

`printf`, `malloc` и `free` не вызываются из обработчика: сигнал может
прервать такую же библиотечную функцию в основном коде. Весь вывод и
освобождение памяти выполняются после возврата из обработчика.

Чтобы сигнал не пришёл между проверкой флага и блокирующим ожиданием ввода,
`SIGALRM` блокируется через `sigprocmask`. `pselect` атомарно снимает блокировку
на время ожидания stdin. Сигнал прерывает ожидание, обработчик меняет флаг,
и `read_query` возвращает статус таймаута. Если готов ввод, `getchar` получает
один байт. Цикл ждёт полную строку; частичный ввод не отменяет таймер.

Буферизация stdin отключена через `setvbuf(..., _IONBF, ...)`: иначе `getchar`
может заранее забрать следующие байты в буфер libc, тогда `pselect` уже не
увидит их в файловом дескрипторе. После отмены таймера `sigpending` проверяет
сигнал, который успел возникнуть на границе завершения ввода.

При таймауте `main` вызывает `print_file`: `lseek` возвращает позицию к началу,
`read` читает блоки, `printf` печатает их. Полный вывод сохраняет содержимое
файла, включая отсутствие завершающего `\n`. Затем освобождается таблица и
закрывается дескриптор.

## Что объяснить на сдаче

- `alarm` сам ничего не печатает: он планирует доставку `SIGALRM`.
- `sigaction` назначает реакцию процесса на сигнал.
- Таймер запускается для каждого запроса и отменяется при полном вводе.
- `pselect` нужен для ожидания ввода без гонки с сигналом; таймер задаёт именно `alarm(5)`.
- Обработчик меняет только флаг; печать файла и очистка ресурсов выполняются в `main`.
- Для деталей таблицы и проверки чисел смотри [задачу 5](../Task_5/README.md).
